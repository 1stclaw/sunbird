# v0.4 Common Foundation

`v0.4-next` is the shared architectural base before the planned gameplay split.

## Common runtime vocabulary

```text
Session        persistent game lifetime
Character      persistent RPG character data
Level          immutable authored structure
Prototype      authored reusable component recipe
World          mutable runtime entities/components/relations
EntityId       integer runtime identity
Simulation     owns one running Level + World
Executor       authoritative command application
TurnPlanner    current turn/JRPG policy, outside Simulation ownership
```

`Simulation::Commands::Buffer` remains an explicit command batch and is intentionally preserved.

## Removed transitional concepts

The first v0.4 experiment introduced several useful but temporary names to discover lifetime boundaries. They are removed from the canonical architecture:

```text
AreaState
ActorState
ActorBindings
ActorRef
Resolver
v0.3 Session compatibility aliases
```

Their lessons survive in simpler ownership:

```text
Session Character :hero
        |
Simulation::Bindings
        |
World EntityId
```

## Level entry model

Persistent player characters are not normal static Level spawns.

```text
Level::Entry(:start)
        +
Prototype(:player)
        +
Session Character(:hero)
        |
        v
Simulation#spawn_character
        |
        v
World EntityId
```

This model is shared by both JRPG and solo directions.

## Genre split point

The common substrate should be accepted before creating `v0.4-solo`.

After the split:

```text
v0.4-next
  Party / TurnPlanner / Dialogue / Battle

v0.4-solo
  single Character / direct combat / realtime policy later
```

Both retain the same World, Level, Prototype, EntityId, Session, Character, Simulation, Commands::Buffer, Executor, and effect boundary.
