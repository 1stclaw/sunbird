# Sunbird v0.4-solo

`v0.4-solo` is the single-character action-RPG research branch built from the common v0.4 runtime foundation.

## Milestone B: fixed-step Kitty input/timing spike

The branch now advances autonomously on a fixed engine clock while deliberately keeping the existing integer grid and command architecture.

```text
Kitty key events
press / repeat / release
        |
        v
Input::Tracker
held + edge state
        |
        v
30 Hz fixed-step App loop
        |
        v
RealtimeController
player movement cadence + NPC cadence
        |
        v
Simulation::Commands::Buffer
        |
        v
Simulation::Executor
        |
        v
World + persistent Effects
```

This milestone proves scheduling and held-input semantics before introducing continuous coordinates, velocity, attack phases, or projectiles.

## Timing policy

Current provisional tuning is centralized in `Sunbird::Realtime`:

```text
engine tick       30 Hz
held player move   5 moves/sec
NPC behavior       2 actions/sec
```

Every engine tick still calls `Simulation#step`, including ticks whose command buffer is empty. `Simulation#step_number` is therefore now a real fixed-step tick counter rather than an input-action counter.

Player movement executes immediately on a new movement-key press, then repeats on its cadence while the key remains held. NPC behavior runs on its own slower cadence and no longer depends on the player producing input.

## Kitty keyboard protocol

On a detected Kitty terminal the Host enables keyboard protocol flags `10` while the alternate screen is active:

```text
0b0010  report event types
0b1000  report all keys as escape-code key events
```

This gives Sunbird actual `pressed`, `repeat`, and `released` events for WASD and other text-producing keys instead of approximating held movement from OS key-repeat.

The keyboard mode is pushed after entering the alternate screen and popped before leaving it.

Legacy decoding remains in `TerminalInput` for tests/fallback use, but the active Kitty runtime uses non-blocking polling.

## Input model

`Input::Tracker` converts physical action events into a per-tick snapshot with separate semantics:

```text
pressed?   edge on the tick a key goes down
held?      remains true until release
released?  edge on the tick a key goes up
```

Movement uses `held?`; attacks, interaction, cancel, and quit remain edge-triggered with `pressed?`.

This prevents holding Space from repeatedly attacking merely because the terminal reports repeat events.

## Gameplay semantics

The solo branch still uses direct in-map combat:

```text
WASD / arrows  held movement
Space          attack facing tile
Enter          interact / advance dialogue
Esc / Q        quit or cancel dialogue
```

There is no `Party` and no `Mode::Battle`.

`Mode::Play` advances the World every fixed tick. Enter only pauses a tick when it actually pushes Dialogue; pressing Enter with no interactable target does not freeze NPC behavior.

Dialogue remains modal and currently pauses World simulation.

## Preserved architecture

This milestone deliberately keeps:

- integer `Component::Position`;
- tile collision and pathfinding;
- `Simulation::Commands::Buffer`;
- `Simulation::Executor`;
- persistent `Effect` values;
- `World` entity lifecycle;
- direct adjacent attacks;
- Kitty graphics rendering.

`TurnPlanner` has been removed from the solo branch. Its reusable movement/idle/wander/chase logic is now in `RealtimeController`, which applies explicit per-tick cadences.

## Still deferred

The next milestone should add real-time action semantics, not another scheduler rewrite:

- attack windup / active / recovery in integer ticks;
- cooldowns;
- one MP-consuming spell;
- a projectile using `Despawn`;
- a pickup using `Despawn`.

Continuous coordinates, velocity, broad-phase collision, sub-cell Kitty placement, and Raylib remain later experiments.
