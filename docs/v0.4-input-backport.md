# v0.4 JRPG backport: executor safety and Kitty input foundation

This backport takes two engine-level improvements from the `v0.4-solo`
experiments and applies them to `v0.4-next` without importing solo gameplay
or scheduling policy.

## Executor safety

`Simulation::Executor` now rejects an `Attack` when the attacker has a local
`Health` component whose current value is zero.

This matters when a command batch was planned before execution. An earlier
command can reduce an actor to zero health; a later queued attack from that
actor must not execute simply because it was already present in the buffer.

This is a runtime legality invariant and does not change JRPG battle policy.

## Kitty keyboard protocol

On Kitty terminals, Host now enables keyboard protocol flags `10` while the
application owns the alternate screen:

```text
0b0010  report press/repeat/release event types
0b1000  report text-producing keys as key events
```

`TerminalInput#poll_events` exposes `Host::KeyEvent` values with:

```text
pressed
repeat
released
```

Legacy decoding remains available.

## Compatibility with the current JRPG loop

This patch deliberately does **not** introduce the solo fixed-step loop.

The existing blocking `Host::Terminal#read_event` path remains compatible with
the current `App`: in Kitty mode it consumes repeat/release events and returns
only a pressed key symbol. Therefore Exploration, Dialogue, and Battle keep
their existing press-driven/turn-driven semantics.

The richer polling API is infrastructure for a later JRPG-specific input-loop
change.

## Input state model

`Input::Tracker` can convert action events into snapshots with separate:

```text
pressed?   edge on key-down
held?      persists until release
released?  edge on key-up
```

`Input::Snapshot#state` is retained for compatibility with the earlier
per-snapshot API.

`Input::Mapper` accepts both legacy key symbols and `Host::KeyEvent` values.
The JRPG mappings remain unchanged: both Enter and Space map to `:interact`.

## Explicitly not imported

- `FixedStep`
- `RealtimeController`
- autonomous NPC cadence
- held movement policy
- Space-to-attack mapping
- direct in-map combat
- removal of Party
- removal of Battle
- replacement of Exploration with Play
